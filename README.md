# MTProxy в Docker

Docker-обёртка для официального [Telegram MTProxy](https://github.com/TelegramMessenger/MTProxy) с Fake TLS, автоматической генерацией секрета и обновлением конфигурации Telegram при каждом запуске.

## Требования

- Linux-сервер с публичным IPv4-адресом;
- Docker Engine и Docker Compose v2;
- открытый TCP-порт на сервере (по умолчанию `443`).

## Быстрый запуск

### Автоматическая установка

На сервере с установленными Docker Engine, Docker Compose v2, Git и curl выполните:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/vanitoo/telegram-mtproxy/refs/heads/main/install.sh)
```

Установщик клонирует проект в `/opt/telegram-mtproxy`, создаст `.env` при первом запуске, попробует определить публичный IPv4 и запустит MTProxy. Повторный запуск сохраняет существующие `.env` и `data/`, обновляет Git-репозиторий и пересобирает контейнер.

### Ручная установка

Скопируйте пример настроек:

```bash
cp .env.example .env
```

Укажите публичный IPv4 сервера в `.env`:

```dotenv
EXTERNAL_IP=203.0.113.10
```

Затем соберите и запустите контейнер:

```bash
docker compose up -d --build
```

На чистой установке первый запуск может занять больше времени: Docker скачает Ubuntu, соберёт MTProxy из исходников, а контейнер загрузит конфигурацию Telegram и создаст секрет.

Посмотрите ссылку для подключения:

```bash
docker compose logs mtproxy | grep -o 'tg://proxy?[^[:space:]]*' | tail -n 1
```

Откройте полученную ссылку на устройстве с Telegram. Если `EXTERNAL_IP` не задан, контейнер попробует определить публичный IPv4 автоматически.

## Настройки

Параметры задаются в файле `.env`:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `443` | Внешний и внутренний TCP-порт MTProxy |
| `STATS_PORT` | `2398` | Внутренний HTTP-порт статистики |
| `DOMAIN` | `www.cloudflare.com` | Домен для маскировки Fake TLS |
| `WORKERS` | `1` | Количество рабочих процессов |
| `EXTERNAL_IP` | определяется автоматически | Публичный IPv4 сервера для NAT и ссылки подключения |
| `PROXY_TAG` | пусто | Необязательный тег, полученный у `@MTProxybot` |

`STATS_PORT` не публикуется на хост в текущем `docker-compose.yml`.

## Управление

Показать состояние и логи:

```bash
docker compose ps
docker compose logs -f mtproxy
```

Перезапустить существующий контейнер без пересборки:

```bash
docker compose restart mtproxy
```

При таком перезапуске контейнер заново загрузит конфигурацию Telegram, но изменения из `.env` не применятся. Чтобы применить новые параметры, пересоздайте контейнер:

```bash
docker compose up -d --force-recreate mtproxy
```

Пересобрать образ и перезапустить прокси:

```bash
./docker_update.sh
```

Или выполнить то же вручную:

```bash
docker compose up -d --build
```

Остановить и удалить контейнер:

```bash
docker compose down
```

Данные при этом сохраняются в каталоге `./data`.

## Постоянные данные и секрет

При первом запуске контейнер создаёт `data/secret`. Этот файл определяет клиентский секрет и ссылку подключения. Сохраните его резервную копию: при потере файла будет создан новый секрет, а старые подключения перестанут работать.

При каждом запуске контейнер загружает свежие файлы `proxy-secret` и `proxy-multi.conf` с `core.telegram.org`. Для первого запуска и последующих обновлений контейнеру нужен доступ в интернет.

### Как обновляется список Telegram

`entrypoint.sh` — главный процесс контейнера. При каждом запуске или перезапуске контейнера он последовательно:

1. загружает новые `proxy-secret` и `proxy-multi.conf` во временные файлы;
2. проверяет, что загруженные данные не пусты;
3. атомарно заменяет ими файлы в `/data`;
4. запускает `mtproto-proxy` через `exec`, передавая ему обновлённую конфигурацию.

```text
Docker container
└── entrypoint.sh              ← обновляет файлы Telegram
    └── exec mtproto-proxy     ← становится главным процессом контейнера
```

Периодического обновления внутри работающего контейнера нет. Чтобы перечитать свежий список Telegram, перезапустите сервис:

```bash
docker compose restart mtproxy
```

Docker снова выполнит `entrypoint.sh`, после чего прокси запустится с обновлёнными файлами. Если загрузка или проверка завершится ошибкой, `entrypoint.sh` остановится и MTProxy не будет запущен с некорректной конфигурацией.

Содержимое `./data`:

| Файл | Назначение |
| --- | --- |
| `.gitkeep` | Сохраняет пустой каталог в репозитории |
| `secret` | Постоянный локальный секрет прокси, создаётся один раз |
| `proxy-secret` | Актуальный серверный секрет Telegram, обновляется при запуске |
| `proxy-multi.conf` | Актуальная конфигурация Telegram, обновляется при запуске |

Чтобы намеренно сменить клиентский секрет, остановите контейнер, удалите только `data/secret` и снова запустите сервис. После этого потребуется заново раздать ссылку всем клиентам.

Не публикуйте содержимое `data/secret` и полную ссылку подключения в открытом доступе.

## Сеть и диагностика

- Разрешите входящий TCP-трафик на выбранный `PORT` в firewall и security group хостинга.
- Убедитесь, что порт не занят другим сервисом. Для проверки на Linux можно использовать `ss -ltnp`.
- Если автоматическое определение адреса не сработало или сервер находится за NAT, явно задайте `EXTERNAL_IP`.
- После изменения `.env` пересоздайте контейнер командой `docker compose up -d`.
- Проверить синтаксис итоговой Compose-конфигурации можно командой `docker compose config --quiet`.
- При ошибке запуска изучите вывод `docker compose logs mtproxy`.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `Dockerfile` | Двухэтапная сборка MTProxy |
| `docker-compose.yml` | Описание сервиса, порта, переменных и тома данных |
| `.env.example` | Пример пользовательских настроек |
| `entrypoint.sh` | Подготовка конфигурации, секрета, NAT и запуск MTProxy |
| `docker_update.sh` | Пересборка, перезапуск и вывод актуальной ссылки |
| `data/` | Постоянные и загружаемые данные прокси |

## Как устроен образ

MTProxy компилируется из официального репозитория в отдельном build-stage на базе Ubuntu 24.04. Финальный образ содержит только бинарный файл и необходимые runtime-зависимости. Процесс MTProxy запускается от системного пользователя `mtproxy`; каталог `./data` подключается в контейнер как `/data`.

Проект не создаёт systemd-сервисы, cron-задачи, системных пользователей на хосте и каталоги за пределами текущей директории.
